# Authentik

Authentik is exposed at `https://authentik.k8s.749rmw.com` through the shared
Envoy Gateway. HTTP requests are redirected to HTTPS.

## Persistent data

- `authentik-data`: 10 GiB RWX claim on `nas-nfs`, mounted at `/data` by both
  Authentik deployments. This stores uploaded files such as application icons
  and branding.
- `data-authentik-postgresql-0`: 20 GiB RWO claim on `nas-nfs`, created by the
  bundled PostgreSQL StatefulSet. Its StatefulSet retention policy and the
  StorageClass reclaim policy are both `Retain`. PostgreSQL runs as UID 1024
  and GID 100 to match the Synology NFS squash mapping used by this share.

The encrypted `authentik-config` Secret is generated by the `cluster-secrets`
Application. It contains the Authentik secret key, PostgreSQL credentials, and
external base URL. Do not change the secret key after first installation.

## First deployment

All applications use manual sync. Sync them in this order:

1. `root` to create the two Authentik child Applications.
2. `authentik-config` to create the namespace, shared data PVC, and routes.
3. `cluster-secrets` to create `authentik-config` in the new namespace.
4. `authentik` to install the pinned Helm chart and PostgreSQL.

Leave Prune, Force, and Replace disabled for the first sync.

Verify the deployment:

```sh
kubectl -n authentik get pods,pvc
kubectl -n authentik rollout status deployment/authentik-server --timeout=300s
kubectl -n authentik rollout status deployment/authentik-worker --timeout=300s
kubectl -n authentik rollout status statefulset/authentik-postgresql --timeout=300s
kubectl -n authentik get httproute
curl --noproxy '*' -I http://authentik.k8s.749rmw.com/
curl --noproxy '*' -I https://authentik.k8s.749rmw.com/
```

Start the initial administrator setup from the instance root:

`https://authentik.k8s.749rmw.com/`

Authentik redirects the browser into the initial-setup flow after establishing
the setup context. Opening the flow URL directly is denied by Authentik 2026.8.
